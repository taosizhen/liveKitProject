# 会议平台功能增强 v2 — 实现计划（含设计原型先行）

## Context（背景与目标）

现有会议平台为「React Web 端 + Flutter 移动端 + Go 后端 + LiveKit」，已具备音视频、屏幕共享、实时标注、聊天、录制、材料管理。

本轮新增功能，**用户最新反馈已纳入**（相对初版有 3 处调整）：
1. **先看设计图原型**：写业务代码前，先产出可交互 HTML 高保真原型供用户确认视觉与交互。
2. **新增头像上传入口**（PC + App）：用户可上传个人头像。
3. **主持人改为动态规则**（不再用静态 `organizer_id`）：
   - 第一个进入会议的人即为主持人；
   - 老师或管理员（`teacher|admin`）进入时**自动接任**主持人；
   - 老师/管理员下线后，切换为**在场最早加入者**。

功能清单与开发顺序（**②③ → ① → ④**，头像/角色作为前置基础）：

| 阶段 | 内容 |
|---|---|
| 阶段零 | 设计图原型（HTML，用户确认） |
| 阶段一（基础） | 后端 token 注入角色+头像 metadata；头像上传接口；两端上传入口 |
| 阶段二（②） | 动态主持人 + 非主持人静音入会 + 语音活动自动切主位 |
| 阶段三（③） | 举手 + 主持人点名（被点名自动开麦） |
| 阶段四（①） | 同框圆桌（圆形头像排布，不抠图）⇄ 参会列表互为小地图 |
| 阶段五（④） | 远程控制（仅 PC 控制 PC，被控端跑本地 Go 代理） |

## 贯穿性架构约定

**Data Channel 按 topic 分域**，消息统一 JSON 信封 `{src,k,ts,...}`：
- `annotation`（已有，不动）、`signal`（新增：举手/点名）、`remote_control`（新增：远程控制）

**动态主持人算法（跨端确定性一致，零后端状态）**：
1. 后端签 token 时 `SetMetadata` 写入 `{"role":"admin|teacher|student","avatar_url":"..."}`（改 `livekit.go:29 GenerateJoinToken`，加 role/avatarURL 参数；调用处 `livekit_handler.go` 传入）。
2. 前端/Flutter 从 `participant.metadata` 解析角色与头像，从 `participant.joinedAt` 取加入时间。
3. 主持人 = 在场所有 participant（含本地）按 **(角色权重 admin/teacher=0 < student=1, joinedAt 升序, identity 字典序兜底)** 排序的第一个。
4. 监听 `ParticipantConnected/Disconnected/MetadataChanged` 重算。该算法自动满足三条规则：仅学生时最早加入者为主持人；老师/管理员进入因角色权重高立即接任；其下线后回到在场最早加入者。

**角色/头像来源**：角色与头像 URL 都通过 token metadata 进房间，会议内各端无需再查后端。头像上传后**下次入会生效**（token 重签）；本会话内自己上传后本地立即更新自己显示。

**头像上传**：复用现有 storage 服务（`storage.NewService` + `/storage/*path` 静态服务）。新增 `POST /api/v1/users/me/avatar`（登录即可，非 admin）：接收图片→存 storage→更新 `User.AvatarURL`（model.go:60 已有字段）→返回新 URL。

**Data Channel 封装**：Web 新增 `hooks/useDataChannel.ts`（入参 `{topic,onMessage}` 统一挂卸 `RoomEvent.DataReceived`）；`AnnotationLayer` 不动。Flutter 每域一个 controller，沿用 `annotation_controller.dart` 模式。

产出一个**自包含可交互 HTML 原型**（单个文件，浏览器直接打开），覆盖以下界面与交互，供用户确认视觉：

- **举手列表 + 主持人点名**：成员列表中举手徽标、按时间排序、主持人"邀请发言"按钮；被点名 toast
- **头像**：席位/列表显示真实头像（无头像显示首字母），个人资料页头像上传入口样式

## 阶段二（②）：动态主持人 + 静音入会 + 语音切主位

### 时序矛盾的处理
静音入会需在 connect 前定 `audio`，但动态主持人需 connect 后看在场者才算出。**解法：全员静音入会（`audio=false`），连接后用动态算法算 isHost，是主持人则自动 `setMicrophoneEnabled(true)`**（主持人首次会弹一次权限框，可接受；现有 `audio` 自动开麦证明该手势链路可行）。

### Web（`Room.tsx`）
- 新增 `hooks/useDynamicHost.ts`：读 `useParticipants()`+`useRoomContext()`，按算法算 `hostIdentity`、`isHost`；`Connected` 后若 `isHost` 则 `setMicrophoneEnabled(true)`，否则保持静音（兜底再 `setMicrophoneEnabled(false)`）。
- `LiveKitRoom` 固定 `audio={false}`（全员静音入会），主持人由上面的逻辑接管开麦。移除原 organizer_id 透传方案。
- 自动切主位：新增 `followSpeaker`（工具栏开关）、`pinnedKey`（点击缩略图钉住）、`speakerOverride`；`activeTrack` 优先级 = `pinnedKey` > 屏幕共享（永不被抢）> `speakerOverride` > 原固定优先级。
- 监听 `ActiveSpeakersChanged` 取 `speakers[0]`；**生效条件** `followSpeaker && !annotating && !whiteboard && !pinnedKey && 无屏幕共享 && speaker≠自己`；**防抖**：2.5s 内不替换 + 新发言人连续 ~800ms 居首位才切；不能切时侧栏缩略图高亮兜底。
- 主持人 UI 标识：成员列表/席位给主持人加徽标，主持人切换时 toast 提示。

### Flutter（`room_controller.dart`）
- 同算法算 `isHost`/`activeSpeakers`（L237 已监听 `ActiveSpeakersChangedEvent`，扩展保存）。
- L201 `_enableMicrophoneSafely()` 改为：连接后若 `isHost` 才自动开麦，否则保持静音。
- `room_screen.dart` 主渲染源同套优先级；`thumbnail_strip.dart` 发言人高亮 + 主持人徽标。

### 自测
①学生先入会静音，老师后进入自动接任主持人并自动开麦、原主持人降级；②老师下线→在场最早加入者接任；③A 说话 1s 主画面切 A，B 抢话需停 2.5s；④开标注/共享时不切主位仅高亮；⑤Flutter 同步。

## 阶段三（③）：举手 + 主持人点名

### 信令（topic=`signal`，reliable）
```jsonc
{"src":"signal","k":"hand_raise","identity":"u1","name":"张三","ts":...}
{"src":"signal","k":"hand_lower","identity":"u1","by":"hostIdentity","ts":...}
{"src":"signal","k":"hand_sync_req","identity":"new","ts":...}
{"src":"signal","k":"designate","target":"u1","by":"hostIdentity","ts":...}
{"src":"signal","k":"designate_ack","identity":"u1","ok":true,"ts":...}
```

### 状态：纯内存 + 事件溯源（不落库）
各端本地 `Map<identity,{name,ts}>`；新加入者 `Connected` 后 ~500ms 广播 `hand_sync_req`，举手中者重发 `hand_raise` 收敛；`ParticipantDisconnected` 移除。

### 点名自动开麦
主持人 members tab 见举手徽标（按 ts 升序）→「邀请发言」→发 `designate`→被点名端 `setMicrophoneEnabled(true)`（触发权限框即用户同意）→清除自身举手广播 `hand_lower`→回 `designate_ack`→toast。点名按钮渲染前用阶段二的动态 `isHost` 校验。

### 改动文件
- Web：`hooks/useSignalChannel.ts`(新)、`store/signalStore.ts`(新)、`Room.tsx`(改)、`types/index.ts`(改)
- Flutter：`signal_controller.dart`(新)、`models/signal.dart`(新)、`room_controller.dart`(改)、`members_panel.dart`(改)、`room_screen.dart`(改)
- 后端：无

### 自测
举手即时可见且有序；重进 500ms 恢复；点名后自动开麦并清除举手；Flutter↔Web 互通（核心回归）。

## 阶段五（④）：远程控制（仅 PC 控制 PC，移动端只观看）

### 链路
控制端 Web（透明事件层捕获键鼠，归一化 0..1）→ DataChannel `remote_control`（reliable）→ 被控端 Web（还原物理像素）→ `ws://127.0.0.1:17653`（仅回环）→ Go 桌面代理（SendInput 注入）→ OS。

### 信令（topic=`remote_control`）
`rc_request/rc_accept{agentReady}/rc_reject{reason:declined|no_agent}/rc_end/rc_ping(心跳5s)` + 高频 `rc_input{type:move|down|up|wheel|key,x,y,button,dy,key,down}`。

### 桌面代理（新增 `desktop-agent/` Go module）
**实现调整**：robotgo 依赖 CGO，无法在 WSL 中交叉编译 Windows exe，改用 `golang.org/x/sys/windows` 直接调用 user32 `SendInput`（纯 Go，`GOOS=windows CGO_ENABLED=0` 即可交叉编译）；DPI 感知改用启动时调用 `shcore.SetProcessDpiAwareness(2)`（等效 manifest，无需嵌入 .syso）；托盘省略，以控制台日志 + Web 端"被控中"状态条替代。
产出单 exe；仅绑回环 WS；握手校验一次性 session token；单会话；全局快捷键（Ctrl+Alt+Esc）强制终止。

### 授权流程
被控端正共享全屏→控制端「请求控制」`rc_request`→被控端弹窗允许/拒绝→允许则检代理连通（不通 `rc_reject{no_agent}`+引导下载）→生成 token `rc_accept`+与代理建 WS→控制态→任一端 `rc_end`/超时/快捷键/停共享→销毁。

### 坐标映射
控制端叠层捕获 pointer/wheel/key，**扣除 `object-fit:contain` 黑边**按 `videoWidth/Height` 归一化；`setPointerCapture` 防拖出；move 事件 rAF 节流 ~30ms。被控端归一化×物理分辨率还原。

### 安全
代理仅回环；token 一次性随 `rc_end` 失效；仅动态主持人（或被 `rc_grant` 授权者）可发起且目标须在共享；被控端显式同意+一键终止；信令走 LiveKit 加密 DC；**代理侧强制校验 session token**（防伪造，最后硬门槛）。

### 自测
两台 PC：全流程；点击/拖拽/滚轮/键盘（含 Ctrl）复现；125%/150% DPI 无偏移；快捷键即断；停共享自动结束；无代理引导下载。联调顺序：代理独立联调→接信令→安全检查表。
