# 在线会议协作平台 — 产品需求规格说明书 (PRD)

> 版本：v1.0 · 最后更新：2026-01

---

## 1. 产品概述

### 1.1 产品愿景
面向教育机构与在线协作场景的轻量级会议平台，提供从预约、通知、实时音视频、会议内协作（材料分发、聊天、录制）到会后归档的完整闭环。

### 1.2 核心价值
- **一键入会**：组织者创建会议后分享链接，参会者无需注册即可快速加入
- **音视频稳定**：基于 LiveKit 的 SFU 架构，支持百方级实时通话
- **会后复用**：自动录制生成回放链接，会议材料永久可查

### 1.3 用户角色

| 角色 | 描述 | 典型权限 |
|---|---|---|
| **管理员 (admin)** | 系统运营者 | 用户管理、全局配置、查看所有会议 |
| **老师 (teacher)** | 课程组织者 | 创建会议、邀请参会者、开始/结束会议、上传材料 |
| **学员 (student)** | 参会者 | 接受邀请、加入会议、发言聊天 |

## 2. 功能需求

### 2.1 账号体系

| ID | 功能 | 描述 | 角色 |
|---|---|---|---|
| A-01 | 注册 | 邮箱 + 密码 + 姓名 | 所有 |
| A-02 | 登录 | 邮箱 + 密码 → JWT Access Token + Refresh Token | 所有 |
| A-03 | 刷新 Token | 用 Refresh Token 换 Access Token | 所有 |
| A-04 | 获取当前用户 | `GET /api/v1/auth/me` | 所有 |
| A-05 | 用户管理 | 管理员创建/禁用/修改角色/删除用户 | admin |
| A-06 | 用户建议搜索 | 所有登录用户可查（支持 q 参数） | 所有（用于邀请） |

### 2.2 会议管理

| ID | 功能 | 描述 | 角色 |
|---|---|---|---|
| M-01 | 创建会议 | 标题、描述、起止时间、类型（辅导/小班课/直播）、可预选参会者 | teacher/admin |
| M-02 | 会议列表 | 按状态过滤（待开始/进行中/已结束/已取消）、分页 | 所有 |
| M-03 | 会议详情 | Tab 展示：基本信息 / 参会人员 / 录制回放 / 会议材料 | 参会者 |
| M-04 | 取消会议 | 组织者取消未开始的会议 | 组织者 |
| M-05 | 标记加入 | 用户确认接受邀请，状态改为 confirmed | 参会者 |
| M-06 | **邀请参会者** | 组织者在会议详情页点击「邀请参会者」→ 搜索用户 → 多选 → 提交 | 组织者 |
| M-07 | **会后删除** | 会议结束后，组织者/管理员可彻底删除会议，同时删除其录制视频与全部材料（不可恢复） | 组织者/admin |
| M-08 | **邮件通知** | 创建会议后自动给参会者发邀请邮件（发件人显示为创建人）；创建时间距开始 ≥8 小时时，会前 8 小时再发一次提醒 | 系统 |

### 2.3 实时会议（Room）

| ID | 功能 | 描述 | 角色 |
|---|---|---|---|
| R-01 | 获取 LiveKit Token | 后端根据 meetingID 生成 LiveKit Join Token，前端用 `@livekit/components-react` 入会 | 参会者 |
| R-02 | 开始会议 | 组织者进入 Room 时自动把会议状态改为 `in_progress` | 组织者 |
| R-03 | 音视频控制 | 麦克风/摄像头开关、屏幕共享（基于 LiveKit WebRTC） | 参会者 |
| R-04 | 会议内聊天 | WebSocket 实时收发，HTTP 拉取历史记录 | 参会者 |
| R-05 | 会议材料 | 组织者上传参考文件，参会者查看/下载 | 组织者上传，参会者查看 |
| R-06 | 屏幕共享 | 基于 LiveKit `setScreenShareEnabled`，共享画面自动成为主画面 | 参会者 |
| R-07 | 静态标注 | 画笔 / 矩形 / 圆形 / 箭头 / 文字，落笔后持久保留，通过 Data Channel 多人实时同步 | 参会者 |
| R-08 | 动态标记 | 激光笔轨迹，1.5 秒自动淡出，用于临时指示 | 参会者 |
| R-09 | 白板 | 一键切换白色画布覆盖视频，用于讲解与板书 | 参会者 |

### 2.4 录制

| ID | 功能 | 描述 | 角色 |
|---|---|---|---|
| REC-01 | 注册录制 | 会议内触发录制时，前端调后端写入元数据 | 组织者 |
| REC-02 | 完成录制 | 录制结束后回填文件地址、时长、大小 | 系统/组织者 |
| REC-03 | 录制列表 | 会议详情页展示所有录制回放 | 参会者 |
| REC-04 | 删除录制 | 组织者或管理员删除 | organizer/admin |
| REC-05 | 浏览器合成录制 | `canvas.captureStream()` + `MediaRecorder` 合成「视频 + 标注 + 白板」画面，并烧入会议水印（会议名 + 录制人）与实时时间戳/REC 标识，停止后上传至后端 | 参会者 |

## 3. 会议邀请流程（重点说明）

```
组织者打开会议详情页 MeetingDetail
        │
        ▼
┌──────────────────────────────┐
│ 是否是组织者？                 │
│ (currentUser.id ===           │
│  meeting.organizer_id)        │
└──────────┬───────────────────┘
      Yes  │        No
           ▼
   ┌────────────────────────┐
   │ Tab 栏右侧显示按钮       │
   │ 「＋ 邀请参会者」         │
   └────────────┬───────────┘
                │ 点击
                ▼
   ┌──────────────────────────────┐
   │ InviteDialog 弹窗             │
   │ 1. 输入姓名/邮箱搜索           │
   │ 2. 排除已在会中的用户          │
   │ 3. 多选 → 「邀请 N 人」提交    │
   └────────────┬─────────────────┘
                │ POST /api/v1/meetings/:id/invite
                ▼
   ┌──────────────────────────────┐
   │ 后端校验：                      │
   │ - organizerID === 当前用户ID    │
   │ - 跳过组织者本人 & 已在会者     │
   │ - 校验被邀请用户 active         │
   │ → 返回 added 数量              │
   └────────────┬─────────────────┘
                │
                ▼
   前端 reload() 刷新参会人员列表
```

## 4. 用户旅程

### 4.1 组织者
```
登录 → 创建会议（填标题/时间）→ 会议详情页 → 邀请参会者（搜索+多选）→
  → 到点点击「开始会议」→ 进入 Room → 上传材料 / 发起聊天 →
  → 录制 → 结束会议 → 会后查看录制回放
```

### 4.2 参会者
```
登录 → 工作台收到邀请 → 点击会议 → 会议详情页确认加入 →
  → 开始时间到达 → 点击「进入会议」→ Room 内音视频 + 聊天 + 看材料
```

### 4.3 管理员
```
登录 → 侧边栏「用户管理」→ 创建/封禁账号 → 修改用户角色
```

## 5. 验收标准

- [ ] 注册/登录全流程可走通，JWT 正常刷新
- [ ] 组织者创建会议后可在会议详情页看到「邀请参会者」按钮
- [ ] 点击邀请按钮弹出对话框，可搜索、多选、提交
- [ ] 被邀请者打开会议详情页能看到自己已在参会列表中
- [ ] 双方进入 Room 后音视频互通（LiveKit SFU 正常转发）
- [ ] 聊天消息即时可达，历史可查
- [ ] 管理员侧边栏有「用户管理」入口，可正常操作

## 6. 非功能性需求

| 维度 | 要求 |
|---|---|
| 性能 | 列表接口 P95 < 300ms；入会延迟 < 1s |
| 可用性 | 后端、LiveKit Server、前端三者解耦，单组件挂掉不影响其他 |
| 安全 | JWT 鉴权 + 组织者权限校验；文件上传白名单；CORS 严格限制 |
| 可移植 | SQLite 默认（零外部依赖），PostgreSQL 可选 |
